## 중복 항목 정리 (2026-07-26 추가)
data.json에 "실사용 품목"과 "수지번호 사전 항목(#093~099)"이 공존해 이름이 겹치는 중복이 있었음. 사용자 지적(플라스틱 OTHER vs OTHER)으로 확인·정리:
- 삭제 4건: `OTHER`(→플라스틱 OTHER로 병합), `PVC`(→PVC 제품), `PS`(→PS 제품), `재활용 표시 없는 비닐류`(→재활용 표시 없는 비닐). 각 수지번호 표시('3/6/7')·고유 별명은 대표 항목에 흡수.
- 유지: PET/PP/HDPE/LDPE 사전 항목(이름 충돌 없고 수지코드 검색에 유용). 수지번호 마크 설명은 마크가이드 UI(recycleMarks)가 담당.
- app.js 빠른참조 `OTHER 플라스틱` bin 오류(플라스틱류→일반쓰레기/종량제) 수정.
- 품목 수: 감사 중 109 → 중복 정리 후 105.

## 검색 안 됨 원인 = 브라우저 캐시 (2026-07-26 추가)
사용자가 라이브에서 '즉석밥/햇반' 검색 시 결과 없음 보고. 조사:
- 라이브 사이트 신선 로드는 정상(105품목, 즉석밥→햇반 용기 반환). 코드·데이터·배포 모두 정상.
- 원인: 브라우저가 예전 data.json(햇반 추가 전)을 캐시. GitHub Pages 기본 max-age로 최대 수분간 stale.
- 조치(캐시 버스팅): app.js의 `fetch('data.json')` → `fetch('data.json?v=' + Date.now())`로 데이터 항상 최신 로드. index.html의 app.js/styles.css 참조에 `?v=` 버전 부여(배포 시 토큰 갱신).
- 추가 방어: Supabase 라이브러리(CDN) 미로드 시에도 가이드/검색/마크가이드가 동작하도록 `supabaseClient` 생성 null-가드 + 초기화 try/catch 분리(인증·수강신청만 우아하게 degrade). 정상(CDN 로드) 시 동작은 동일.
